# Experiment Skeleton、实验级缓存与统一 ID

## 一、主实验折叠与 Experiment Skeleton

默认一篇研究一行，但一篇论文可能同时包含不同对象、目标、信息角色和评估设计。只在条件差异会影响主结论、矩阵归属或演化关系时拆分子实验，避免为每个步长、基线或损失单元格无限拆行。

### 主实验单元

以“研究对象/市场/样本族 × 核心研究目标口径 × 主评估设计”为折叠键生成 `experiment_id`。同一单元内保留：

- 多步长、子样本和时期；
- 输入、控制与基线；
- 方法规格；
- 支持与失败方向；
- 指标、成本和证据定位。

典型字段：

- `experiment_id`、`paper_id`、`skeleton_version`；
- `object_scope`、`target_definition`、`evaluation_design`；
- `horizons_supported`、`horizons_failed`；
- `samples`、`inputs`、`controls`、`baselines`、`metrics`；
- `evidence_ids`、`condition_and_limits`。

不设置固定的每篇实验数量上限；设计实质变化时仍拆分。不得为压缩记录而丢掉相反结果或条件依赖。

### 两步生成与纠偏

1. 轻量解析先根据章节、公式和表图生成候选 Experiment Skeleton，记录稳定序号和证据定位。
2. 完成结构与定位校验后冻结该版骨架，后续字段提取和矩阵配对都使用同一份骨架。
3. 若发现漏拆、误并或表号错配，保留原版本、变更理由和受影响输出，签发新骨架版本并只更新受影响单元。

骨架修订不得根据希望得到的结论反向选择实验划分。

## 二、实验级缓存

论文登记表继续保存研究实体级信息，以下记录放在缓存中：

- 主实验骨架及版本；
- 实验级目标、输入、控制、基线和指标；
- 矩阵两个轴值及同现证据；
- 多市场、多步长、多时期的支持与失败结果；
- 各字段的适用范围和证据 ID。

矩阵必须从实验级配对聚合，而不是从论文级字段的笛卡尔积拼接。展示快照需保存生成每格所用的 `experiment_id` 和证据 ID。

## 三、统一 ID 体系

| ID | 用途与规则 |
| --- | --- |
| `run_id` | 一次完整调研运行及其配置边界 |
| `snapshot_id` | 同一次冻结展示的输入快照 |
| `paper_id` | 去重归并后的研究实体，如 `P001` |
| `entity_id` | 检索和筛选阶段的候选实体；发布后建立 `entity_id → paper_id` 映射 |
| `experiment_id` | 主实验单元，关联论文、目标、评估设计和证据 |
| `evidence_id` | 原文证据记录，关联具体版本和精确定位 |
| `edge_id` | 图谱边全局唯一标识，按下列前缀分层 |
| `record_id` | 筛选、属性、边或审计的候选/裁决记录 |

### 边 ID 前缀

- `SKxxx`：协议字典生成的概念骨架边。
- `Exxx`：`evolution_edges.csv` 中的已核语义边。
- `CExxx`：候选与裁决缓存中的候选边。
- `CITxxx`：原始引文边。

完整 ID 不得跨层碰撞。历史资料如使用其他前缀，保留原值并建立映射，不回溯篡改。

## 四、缓存记录与权威职责

| 记录 | 关键内容 |
| --- | --- |
| 运行与来源 | `run_id`、范围、截止日、查询、来源、批次、分页、原始返回和处理日志 |
| 原文证据 | `evidence_id`、`paper_id`、版本、路径/链接、物理页/刊页、章节、公式、表格行列、原文摘录或坐标 |
| 筛选记录 | `entity_id`、原始记录/版本 ID、拟纳入状态、理由、证据 ID、缺失项和发布后 `paper_id` |
| 实验记录 | `experiment_id`、骨架版本、目标/输入/控制/基线、条件、指标和证据 ID |
| 候选与裁决 | `record_id`、对象 ID、字段、取值、角色、适用范围、`evidence_ids`、`decision_status`、原判、修改和理由 |
| 展示输入 | `snapshot_id`、矩阵格、论文集合、实验配对、分支、报告主张和证据 ID |

`decision_status` 使用 `candidate`、`needs_review`、`accepted`、`rejected`，只表示流程状态，与核心/关联/排除的纳入类别分开。已确认的排除决定也可以是 `accepted`。

### 权威分工

- `paper_id` 是登记表、证据、实验和展示缓存之间的主外键。
- 登记表不重复维护全部 `entity_id`、全量证据 ID 或第二套流程状态。
- `evolution_edges.csv` 只发布已核语义边，并保留多值 `evidence_ids`。
- 候选边、撤销记录和 `decision_status` 以边裁决缓存为权威来源。
- 三核心文件与原始引文缓存负责文献总账和主图谱的最小重建；矩阵、论文卡和完整报告还需要展示快照及实验证据缓存。

## 五、证据记录

每条证据至少保存：

- `evidence_id`、`paper_id`、可选 `experiment_id`；
- 文献版本、稳定链接或本地相对路径；
- 物理页、刊页、章节、公式、表格及必要的行列；
- 原文摘录或坐标及匹配状态；
- 支持的字段、关系或结论。

跨段、公式和表格可组合多个 `evidence_ids`。版本变化时不得沿用旧版页表定位。
